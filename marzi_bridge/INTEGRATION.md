# Marzi Bridge — Phase 1 Integration Status

_Last verified: 2026-07-19 on bench `/Users/prabhaskalyan/frappe-bench`, site `marzi.localhost`._

This doc answers two questions: **what is actually wired up today**, and **what is
left to make Phase 1 "fully integrated"** in the sense of being visible and usable,
not just present on disk.

> TL;DR — the app is installed and the whole proxy layer is built and unit-tested,
> but it is **headless**: there is no Desk UI, no user is OTP-linked, and the Desk
> web server isn't the thing currently serving port 8000 (Docker is). None of these
> are code bugs — they're the last integration/runtime steps.

## 0. Data layer — Virtual DocTypes (2026-07-19)

The dashboard entities are now real Frappe **List/Form** screens backed live by the
backend APIs (no local tables, no sync — `is_virtual=1`). Reusable base:
`marzi_bridge/api_document.py` (`ApiDocument`) implements the whole virtual-doctype
contract onto `MarziClient`; each entity just declares endpoint/service/envelope/id.

| DocType | Endpoint | Service | Mode | Notes |
|---|---|---|---|---|
| Marzi Speaker | `/speakers` | v1 | **CRUD** | hand-built pilot; read/write verified against the type |
| Marzi Event | `/events` | v1 | read-only | scalar fields only (nested blocks omitted) |
| Marzi Booking | `/admin/bookings` | v1 | read-only | single record loaded from the list (no GET-by-id) |
| Marzi Group | `/groups` | v1 | read-only | `name`→`group_name` (Frappe reserves `name`) |
| Marzi Testimony | `/admin/testimonials` | v1 | read-only | `name`→`person_name` |
| Marzi User | `/users` | v1 | read-only | camelCase keys aliased to snake_case |
| Marzi Media | `/media` | v1 | read-only | nested envelope `data.items` / `data` |

Generated by `scripts/gen_doctypes.py` (declarative specs → DocType JSON +
controller). All 7 synced, `is_virtual`, controllers pass Frappe's static-method
validation, and `frappe.get_list(...)` dispatches through to the backend (currently
stops at the clean "link your phone first" gate — see Gap B). They're linked in the
**Marzi Bridge workspace → Data** card.

**Why most are read-only:** several entities' create/update bodies differ from their
read model (e.g. Testimony reads `image_url` but creates with `image`). Rather than
ship broken writes, writes are enabled per entity after checking bodies against the
live API. **Deferred entirely for now:** campaigns / pages / templates (publishing,
config-heavy nested JSON) and the action-style modules (moderation, escalations,
tracking, whatsapp, payments) — these don't map onto a plain List/Form.

## 2. What "not integrated" actually means here (the gaps)

### Gap A — Desk UI presence  ⟵ this was why it looked "not integrated"
**Partially closed (2026-07-19):** a public **Workspace "Marzi Bridge"** now ships
with the app (`marzi_bridge/marzi_bridge/workspace/marzi_bridge/`) — it appears in the
Desk left nav with shortcuts + a Configuration card linking to `Marzi Bridge Settings`
and `Marzi User Link`. Synced into the site via `bench migrate`; verified in the DB.
The app also has its own tile on the **`/apps` launcher** via the `add_to_apps_screen`
hook in `hooks.py` (gated by `permissions.check_app_permission` → Marzi Admin / System
Manager), routing to `/app/marzi-bridge`.
_Still deferred (user's call):_ a dedicated "Link your phone (OTP)" form page so
linking is clickable instead of CLI-only. For now linking stays on the CLI.

### Gap B — No user is OTP-linked (+ send-otp returns 404)
`link_status` → `{"linked": false}`. Until an ADMIN/SUPER_ADMIN phone is linked, every
authenticated proxy call returns "link your phone first" and the smoke test reports
`SKIP not linked`. **This step needs a real OTP SMS, so only you can do it.**

⚠️ **Known issue (2026-07-19):** `send_otp` currently fails with **`Failed to send OTP: 404`**
against the configured dev host. That means the path the proxy calls (`/v1/auth/send-otp`)
does not exist at `v1_base_url` as set. Before the OTP link can work, confirm the real
send-otp / verify-otp routes on the dev backend (check `Backend-for-org` routes or
`API_DOC.md`) and reconcile `auth/otp.py` + `v1_base_url`. Parked for now per your call.

### Gap C — Desk web server isn't serving natively
Port 8000 is currently held by **Docker** (`com.docker`), not `bench start`. There's a
dockerized stack (`docker-compose.yml`, `DOCKER.md`) in this repo. Decide **one** path:
run everything in Docker, **or** run the native bench — don't half-run both, or 8000
collides. (The native bench also has a trimmed `Procfile` with no socketio/asset watch,
and Desk assets were never built — see Gap D.)

### Gap D — Desk assets not built
The bench was built `--skip-assets` (fork wants Node 24; box had 22/23). The headless
API works fine without assets, but the **Desk UI won't render properly** until
`yarn install` (Node 24) + `bench build` is run and `Procfile.full` is restored.
Only matters once you want the Desk UI (i.e. after Gap A).

### Gap E — 3 services still unconfigured
`blog_base_url`, `whatsapp_base_url`, `payments_base_url` are intentionally unset (only
prod Lambdas are known). Those endpoints return a clean "base URL not configured" error
and the smoke test marks them `SKIP`. Set dev hosts when available.

## 3. What to do next — ordered checklist to finish Phase 1

**Step 1 — Pick a runtime and make Frappe reachable.**
Choose Docker _or_ native bench.
- Native: free 8000 (stop the Docker stack), start the isolated MariaDB if down, then
  `cd /Users/prabhaskalyan/frappe-bench && bench start`. Open `http://marzi.localhost:8000`.
- Docker: follow `DOCKER.md`; confirm the container has `marzi_bridge` installed on the site.

**Step 2 — Build Desk assets (only if you want the UI).**
On Node 24: `cd apps/frappe && yarn install`, then `bench build`, then restore
`Procfile.full` (currently trimmed) so socketio + asset watch run.

**Step 3 — Desk surface (Gap A).**
- ✅ **Done:** Workspace "Marzi Bridge" (shortcuts + Configuration card). Reload Desk
  with a hard refresh to see it in the left nav.
- ⬜ **Deferred:** a Desk Page/form wrapping `auth.otp.send_otp` + `verify_otp` so
  linking is clickable. Do this once the backend OTP path is confirmed (see note below).

**Step 4 — Link your phone (OTP) — only you can do this.**
```bash
bench --site marzi.localhost execute marzi_bridge.auth.otp.send_otp   --kwargs "{'phone':'+9198XXXXXXXX'}"
bench --site marzi.localhost execute marzi_bridge.auth.otp.verify_otp --kwargs "{'phone':'+9198XXXXXXXX','otp':'123456'}"
bench --site marzi.localhost execute marzi_bridge.auth.otp.link_status   # -> {"linked": true, ...}
```

**Step 5 — Prove live parity.**
```bash
bench --site marzi.localhost execute marzi_bridge.verify.smoke_test
```
Expect PASS on v1/v3/publishing/tracking endpoints; `SKIP base URL not set` on
blog/whatsapp/payments until Step 6.

**Step 6 — Configure the remaining 3 services (optional / when dev hosts exist).**
Set `blog_base_url`, `whatsapp_base_url`, `payments_base_url` in `Marzi Bridge Settings`.

**Step 7 — Assign roles to real users.**
Give `Marzi Admin` to each Frappe user who should reach the proxy; have each of them
do their own OTP link (per-user tokens preserve backend audit identity).
